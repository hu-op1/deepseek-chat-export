# 主题图谱 — 设计文档

日期：2026-11-04
状态：已实现，待用真实模型跑全量

## 1. 目标

回答一个问题：**这两年我都在关心什么，它是怎么变的？**

不是知识图谱（实体-关系三元组），而是**主题共现网络 + 时间河流**。
前者要抽三元组、成本高一个数量级，而且回答不了"我关心什么"这种问题。

## 2. 数据事实（实测）

| 项 | 值 |
| --- | --- |
| 对话 | 497 |
| 消息 | 4,617 |
| 正文 | 634 万字符（约 300-500 万 tokens） |
| 跨度 | 2026-07-20 → 2026-11-04 |
| 月度分布 | 7月 75 / 8月 112 / 9月 152 / 10月 137 / 11月 21 |
| 长度 | 中位 4,403 字符，最大 48 万字符 |
| 结构 | **93% 是 ≤20 条的短对话**，38% 是一问一答 |

两条由此推出的设计约束：

1. **按对话打标签，不按消息**。4617 条消息切碎后，每一片都不足以下判断。
2. **输入必须截断**。最长单个对话 48 万字符，超过任何上下文窗口。

## 3. 为什么不是"用嵌入直接聚类"

嵌入聚类产出的是**簇**，而簇没有名字——还得再让模型给每个簇起名，多两层间接、丢了可解释性。

而且簇的边界由向量距离决定，`vLLM` 和"摩托车"在某组向量里可能比想象中近。

改用"**模型打标签 → 标签归并**"两步：

- 每个标签都是人话，可以人工修正
- 归并成固定词表后，聚合结果稳定可复现
- 嵌入降级为可选校验，不是必经之路

> 结论：这套东西的核心不是嵌入模型，是标注与归并。嵌入真正不可替代的场景是"我忘了原词"（语义搜索），那是另一个功能。

## 4. 流水线

```
data/sessions/*.json
      │  截断成开头+中段+结尾（上限 6000 字符）
      ▼
A. 标注    每个对话一次调用 → memory/topics/<id>.json（可人工改）
      │
      ▼
B. 归并    全部原始标签 → 约 30 个规范主题 → memory/canonical.json
      │
      ▼
C. 聚合    → memory/graph.json
      │
      ▼
D. 渲染    → memory/graph.html（自包含，双击打开）
```

### A 标注

输出严格 JSON：`topics[{label,weight}]`、`entities[{name,type}]`、`summary`。
`normalizeAnnotation` 负责清洗：去重、夹紧权重到 0.05-1、丢弃超长标签、限制条数。
**脏数据一律丢，不能塞进图谱。**

结果落盘到 `memory/topics/<id>.json`，已存在就跳过——**断点续跑，也允许手工修改**。

### B 归并

自由标签会分裂（`代码`/`编程`/`写程序` 三个主题），图就废了。

归并提示词三条硬要求：近义合并、**每个输入标签都必须出现在某个 aliases 里**、规范名用 4-10 字中文短语。
`normalizeMerge` 兜底：模型漏掉的标签收进"其他"，绝不静默丢弃。

### C 聚合

产出主题计数、月份分布、共现边（同一对话里共同出现的主题对）、按月的主题构成。

### D 渲染

三个视图共享一份数据：主题流向（河流图）、主题网络（力导向）、详情面板（可点选的图例）。

## 5. 三条"防误导"规则

图表最容易骗人的地方不是画错，是画对了但读错。

| 风险 | 处理 |
| --- | --- |
| 最后一个月只过了 4 天，曲线断崖会被读成"兴趣崩塌" | 覆盖率 < 80% 的末月**不进趋势线**，在标题和注释里单独交代它的数据 |
| 峰值月份用"各主题成员数之和"计算会算错（一个对话算两个主题） | 峰值改用 `countsByMonth` 的真实每月对话数 |
| 20 个小主题合成的"其他"体积很大，压在顶部会盖过真正想看的东西 | 「其他」置底并降低透明度，当成"地面"而不是数据 |

另外：层与层之间留一道纸色细缝（0.9px），否则 8 个暖色会糊成一团。

## 6. 外接模型

统一走 OpenAI 兼容协议，差异收敛成三个参数：`--base-url` / `--model` / `--api-key`。

- 优先请求 `response_format: {type:"json_object"}`；端点不支持时**自动降级**为纯文本解析
- `extractJson` 容忍 md 围栏、前后废话、字符串里的花括号、以及前面有坏片段（逐个 `{` 位置重试）
- 复用了导出器的限流门闸（`createGate`）与指数退避

## 7. 存储

```
memory/
  topics/<id>.json     每个对话的标注（个人数据，已进 .gitignore）
  canonical.json       规范主题与别名映射
  graph.json           聚合结果
  graph.html           可视化页面
```

`memory/` 含对话标题与摘要，**属于个人数据，不入库**。

## 8. 验证

- 纯函数单测：截断、归一化、归并兜底、聚合、残缺月剔除、峰值口径、XSS 转义
- 本地假 OpenAI 服务跑通 A→D 全链路（不消耗额度）
- 无头浏览器截图 + 视觉复核（发现并修掉了三个真问题：断崖、峰值错位、空图表）

## 9. 已知局限

- `updated_at` 是**最后活动时间**，不是创建时间。长对话被重新打开会被算到新月份。
- 只有 5 个月数据，河流图的信息量有限；数据攒到一年会明显更好看。
- 主题质量取决于模型。`--limit 20` 先看小样本，不满意就改提示词重跑。
- 归并是单次调用，模型可能漏标签——`normalizeMerge` 会兜底并在 CLI 里报告，但不会自动重试。
